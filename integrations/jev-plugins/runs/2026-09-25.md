## Cross-cutting observations (not failures; for the maintainer to decide on)

1. **Response `model` is `laya-rl-agent`** for requests sent with `jev-latest` and with
   `jev-1.13.0`. Effects:
   - jev-axi caches the alias as `{"jev-latest": "laya-rl-agent"}` (in `x/k/jev-axi/aliases.json`).
   - switchboard's `diagnostics.resolvedModel` is `null`: its regex
     `^jev-\d+\.\d+\.\d+$` rejects the name. That field is diagnostics only and harmless.
   - The other clients only log the value.
2. **`models.list()` entries have `release_date: ""`.** Both SDKs accept it, since strict
   `str` is satisfied. jev-axi shows empty `released`/`current` columns. The JS SDK passes
   through the extra `loaded` and `default` keys, and the Python SDK ignores them.
3. **`usage.output_tokens` is `0`, and the extra top-level `routing` and `laya_apple` keys
   plus the per-answer `action` key are accepted by every client.** The Python strict model
   ignores them, and the others cast or pass them through. typesafe-mcp shows them to the
   agent verbatim.
4. **A missing `instructions` gets a 422 in both SDKs.** The Python SDK leaves
   `instructions` off the wire for `Noul()`. The JS SDK's `validateQuestions` accepts
   `{type:"noul"}` without instructions. In both cases the server answers
   `422 {"detail":"question is missing instructions"}`, and each SDK surfaces it cleanly:
   - Python: `TypeSafeUnprocessableEntityError`, `.status == 422`,
     `str(e) == "POST http://127.0.0.1:8642/v1/systemone: 422 question is missing instructions"`.
   - JS: `UnprocessableEntityError`, `e.status === 422`,
     `e.message === "422 question is missing instructions"`.

   With retries off, the probe got one attempt, and 422 is not retried anyway. This
   matches upstream Laya, which also requires instructions. The Jev schema makes the field
   optional, so a client that omits it will get this 422.
5. **Canny thresholds vs Laya calibration.**
   - Canny acts on a noul only when the value is ≥ 0.9 or ≤ 0.1.
   - For the done-claim message "Done - I fixed the bug in src/a.ts.", `claims_done` was
     0.8439.
   - For a clearly not-done message ("I am blocked: which database should I use…"), it
     was 0.2962.

   Neither value crosses a threshold, so the Jev answer has no effect on the decision in
   either case. The block came from the deterministic ledger both times. The protocol
   works, but the relax path ("Jev is sure this is not a done claim") did not trigger in
   this sample.
6. **switchboard confidences are very low.**
   - For "Fix a spelling mistake…": `model` 0.036, `effort` 0.062, `context` 0.0016;
     `sufficientContext=false`.
   - For the sharding task: `model` 0.048, `effort` 0.088.

   The default policy's floors are `modelMinConfidence` and `effortMinConfidence`, both
   0.7. `assessInitialRoute` therefore marks both tasks uncertain and picks the fallback
   route `claude-opus / claude-opus-5 / high`:
   - spelling task: adjustment `insufficient-context`;
   - sharding task: adjustments `model-confidence-floor` and `effort-default`.

   The `taskType` answers are sensible: `edit` at 0.964 and `architecture` at 0.696.
   switchboard defines choice `confidence` from probability concentration, so for 4–5
   near-flat options it is low by construction. This is a model-quality or calibration
   question, not a wire-compatibility one.
7. **Latency under fan-out.** The typesafe-mcp items call sent 8 concurrent requests.
   The worst `laya_apple.queue_wait_ms` was about 482 ms (`routing_reason
   ane_backlog_shorter_on_gpu`), and the others about 207 ms. That is far inside
   typesafe-mcp's 60 s timeout, and it is the only concurrency probe in this set.
