# laya-apple 1.5.0: GPU + Neural Engine serving adapts to system load

GPU + Neural Engine serving now adapts to system load. When the Mac is quiet, laya and
laya-typed-decisions run the Neural Engine on a faster asynchronous path, so it no longer
holds up the GPU's results. When the Mac becomes contended, they fall back automatically to
the stable 1.4 execution path. It is on by default and needs no code change:

```bash
pip install -U 'laya-apple[ane]'
```

```python
with Laya.from_pretrained("convaiinnovations/laya-typed-decisions", execution="workers") as model:
    futures = [model.submit(context=c, questions=q) for c, q in requests]
```

## Measured results

On one Apple M4 Max, against the 1.4 path in the same session, with a
closed-loop short stream (128 tokens, one question) beside a long one:
- 154 production episodes of GPU + Neural Engine overlap: laya and laya-typed-decisions;
  product mix, bursts, repeated transitions and a 66-episode typed soak;
- all 154 episodes stayed on the fast path.

| Result | laya | laya-typed-decisions | Source |
|---|---:|---:|---|
| GPU result return, P50 (1.4 path) | **0.035–0.037 ms** (4.28–4.29 ms) | **0.043 ms** (8.60 ms) | [`val_tables.md`](https://github.com/tc3oliver/laya-apple/blob/main/research/coreml-adaptive-breaker/val_tables.md) |
| Throughput against the 1.4 path | 1.042× | 1.038× | same |
| Median episode P99, against the 1.4 path | 0.18–0.19 ms lower | 0.53 ms lower | same |
| Mismatches, routing failures, lost requests, crashes | 0 | 0 | same |

**When the fast path slows down:**
- On a contended Mac the asynchronous path can fall into a slow state: a median short latency
  of 12.3 ms against 10.0 ms.
- In the recovery experiment, 12 episodes were already in that state. In every one, the
  breaker tripped within 40 ms, and latency was back to the 1.4 path's within 164–414 ms
  ([`phase1_tables.md`](https://github.com/tc3oliver/laya-apple/blob/main/research/coreml-adaptive-breaker/phase1_tables.md)).
- No slow state occurred naturally in the 154 validation episodes.

## What else is in it

- **`ane_handoff`:**
  - `None` (the default): on where eligible and available;
  - `False`: always the 1.4 path;
  - `True`: required.
  - `info()["ane_handoff"]` shows its state.
- **laya-multilingual is unchanged.** Its Neural Engine runs in a worker process and does not
  use adaptive execution.
- **If `pyobjc-framework-CoreML` is missing** (it ships in the `ane` extra), or the
  asynchronous models fail their load checks, the instance runs the 1.4 path and warns once.
- **A new parity test** runs the asynchronous path against the goldens: every output equals
  coremltools' exactly.
- **The research behind it is published:**
  - [`research/coreml-adaptive-breaker/`](https://github.com/tc3oliver/laya-apple/blob/main/research/coreml-adaptive-breaker/README.md):
    the detector replay, the recovery experiment, and the release validation;
  - [`research/coreml-staged-handoff/`](https://github.com/tc3oliver/laya-apple/blob/main/research/coreml-staged-handoff/README.md):
    the static route that was closed first.

## Limitations

- **Measured on one Apple M4 Max only.**
- **The first 64 Neural Engine requests** of every GPU + Neural Engine overlap run the 1.4
  path.
- **The fallback's recovery** comes from a separate 12-episode experiment, not from the
  validation runs, where no slow state occurred.
