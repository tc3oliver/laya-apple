# laya-apple 1.6.3: a first `artifacts fetch` compiles once, not twice

A patch release. A first `artifacts fetch` or `artifacts import` of a bucket now compiles the
model for the Neural Engine once instead of twice, and the artifacts it registers no longer
carry a stale `BUILDING.json`. `artifacts prune` and build swaps also survive interruptions.
`predict`, the parity tolerances, the routing rule and the prebuilt-artifact pin are
unchanged.

```bash
pip install -U 'laya-apple[ane]'
```

## One compile per import

Core ML compiles a model for the Neural Engine per path. Until now an import ran the compute
plan, the parity gate and the placement probe on a staged copy, moved the model to its
registered path, and then loaded and probed it again there. A first install paid for two
compiles ([#164](https://github.com/tc3oliver/laya-apple/pull/164)).

Now the staged copy moves to the registered path first, with its manifest withheld. The
checks run there, and the manifest is published with one atomic rename only after they all
pass. Until then the runtime sees no artifact at that path, and a failed or killed import
registers nothing. The checks, the hooks and `PROBE_MAX_RATIO` are the same. A `--force`
replacement still validates in staging first, so it still compiles twice.

Measured on one Mac Studio M4 Max (macOS 27.0, coremltools 9.0) with laya-typed-decisions
L128, each import into an empty cache, three imports per side
([`results.md`](https://github.com/tc3oliver/laya-apple/blob/main/research/import-compile-once/results.md)):

| | Before | After |
|---|---:|---:|
| Import time (`fetch`'s checks) | 145.7 / 146.1 / 145.9 s | 75.4 / 75.6 / 75.3 s |
| New Core ML compile bundles | 6 | 3 |
| Compile cache added | 2.98 GB | 1.49 GB |
| First load by another process, afterwards | 0.34 s (median) | 0.33 s |

Before is `main` one commit after 1.6.2. After is the research prototype of this change; the
shipped `artifacts import` was measured separately (below). With the method of
[#121](https://github.com/tc3oliver/laya-apple/issues/121), three `artifacts import` runs of
the same bucket went from 151.1, 154.0 and 149.2 s to 76.4, 91.4 and 78.9 s. The 91.4 s import
is not explained.

## `BUILDING.json` stays out of registered artifacts

Fixed in [#161](https://github.com/tc3oliver/laya-apple/pull/161)
([#160](https://github.com/tc3oliver/laya-apple/issues/160)).

- `artifacts import`, `artifacts fetch` and `artifacts build` wrote an in-progress marker into
  their staging directory and then renamed the whole directory into place, so every artifact
  they registered kept it. The marker is now removed just before the rename.
- `artifacts prune` reads that marker before it checks a staging directory's age, and checks
  both again just before it deletes, so a directory whose import has just finished or is still
  running is not deleted.
- A forced `artifacts build` whose move into place fails now puts the previous artifact back.
  It used to leave it at `.old-<pid>` with nothing registered.

## `artifacts prune` and build swaps survive interruptions

Fixed in [#166](https://github.com/tc3oliver/laya-apple/pull/166). `artifacts prune` claims a
path with one rename before it deletes anything, so an import that lands in between is not
deleted, and an interrupt right after a build's move into place keeps the new artifact
registered. A published copy stranded by a crashed prune is reported with an `mv` hint, never
deleted.

## Limitations

- One machine, one model, three imports per side. Only macOS 27.0 (26A428) was measured; the
  macOS 26 import path was not. No second machine has checked this.
- Compiles are counted from Core ML's e5rt cache directories, a proxy, not an API. The
  `artifacts import` re-run was not preregistered, and its 91.4 s import is unexplained.
- It does not remove the compile, only the second one. The import still pays it, and the
  first runtime load of an artifact at a new location still compiles: about 210 s for
  laya-typed-decisions (64/96/128) on macOS 27.0
  ([`results.md`](https://github.com/tc3oliver/laya-apple/blob/main/research/coreml-compile-cache/results.md)).
  `ane_startup="background"` serves on MLX meanwhile.
- Core ML's compile cache still grows without eviction, and Core ML keeps it per process
  name, so a process with a different name may compile again. laya-apple never evicts it,
  and `artifacts prune` does not touch it.
- Artifacts registered before 1.6.3 keep their copy of `BUILDING.json`. Nothing reads it, and
  it goes away when the artifact is replaced.
- The [1.6.2](https://github.com/tc3oliver/laya-apple/blob/main/docs/releases/v1.6.2.md#limitations)
  limitations not repeated here still apply.

## Upgrading

- No code change needed, and nothing to rebuild or re-fetch.
- The next `artifacts import` or `artifacts fetch` of a bucket removes an unpublished
  directory that a killed import left behind. `artifacts prune` lists one once its import has
  exited and it is older than an hour.
