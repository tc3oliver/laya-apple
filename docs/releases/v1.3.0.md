# laya-apple 1.3.0: replace the Jev API with a local backend on your Mac

1.3.0 adds `laya-apple serve`, a local alternative to the Jev API. It is a loopback-only
HTTP server with a Jev-compatible API (`POST /v1/systemone`) that answers with upstream
[Laya](https://github.com/NandhaKishorM/laya), running on the Mac's MLX GPU and Apple
Neural Engine. An existing Jev client keeps working when its base URL points at it; its
code does not change.

```bash
pip install 'laya-apple[serve,ane]'
laya-apple serve                                   # http://127.0.0.1:8642
export TYPESAFE_BASE_URL=http://127.0.0.1:8642     # then run your Jev client as usual
```

laya-apple is not affiliated with TypeSafe or Jev. The API is compatible; the model is not
the same. What 1.3.0 guarantees is fidelity to upstream Laya: the answers are Laya's, not
Jev's.

## What's new

- **`laya-apple serve`** (the `[serve]` extra). It follows upstream `laya.serve` 0.3.20's
  wire format: request fields, limits, status codes and the `routing` block.
  - **`--model auto`** (the default) picks the checkpoint per request from the state's
    language, with upstream's own router logic: `laya` for English, `laya-multilingual`
    otherwise.
  - **Concurrent GPU + ANE serving.** There is no global inference lock. Short
    single-question decisions go to the Neural Engine, and long or multi-question ones to
    the GPU. Every response carries a `laya_apple` block naming the checkpoint and the
    device that answered, and why.
  - **Loopback only by default.** It answers only loopback `Host` headers, requires
    `Content-Type: application/json`, and refuses a non-loopback bind unless you pass
    `--allow-remote` and set `LAYA_API_KEY`.
  - Docs: [`docs/serve.md`](https://github.com/tc3oliver/laya-apple/blob/main/docs/serve.md).
    The HTTP API is part of the stable API
    ([`docs/api.md`](https://github.com/tc3oliver/laya-apple/blob/main/docs/api.md)).
- **Parity tracks upstream Laya 0.3.20,** not 0.3.5. Prompt building, question validation
  and the answer format follow 0.3.20, and every answer gains `answer_confidence`. The
  goldens are re-recorded from 0.3.20; every earlier case is unchanged. See "Upgrade notes"
  for what behaves differently.
- **`RuntimeInfo.truncated`** reports when a state was cut to fit the checkpoint.

## Limits

- **No Jev accuracy claim.** Laya is a different, smaller model. Only fidelity to upstream
  Laya is measured.
- **Client thresholds tuned on Jev.** Canny and switchboard act only on confidences above
  thresholds tuned for Jev. Laya's answers did not cross them in the tested runs, so both
  took their own fallback paths.
- **No performance claim for `serve`.** Its latency, its throughput and its effect on a
  local LLM that shares the GPU are not measured.
- **`auto` routes between English and multilingual only.** Upstream's opt-in
  typed-decisions workflow detection (`LAYA_AUTO_TASK`) and caller language hints are not
  implemented; name the checkpoint or use `--model`.
- **Deliberate differences from upstream:** status 415, 421 and 503, and 422 or 400 on
  some malformed requests that upstream answers 200 or 500
  ([`docs/serve.md`](https://github.com/tc3oliver/laya-apple/blob/main/docs/serve.md)).
- **One machine, one date.** Every result above is from one Apple M4 Max. The existing
  limitations of the runtime all still apply
  ([README](https://github.com/tc3oliver/laya-apple#limitations)).

## Upgrade notes

- **`serve` needs its extra:** `pip install 'laya-apple[serve]'`, or `[serve,ane]` for the
  Neural Engine path. Without it, `laya-apple serve` exits with a message naming the
  extra. The base install is unchanged.
- **The default port is 8642,** not upstream's 8000, which local LLM servers often use.
- **Behaviour that follows upstream 0.3.20 now** (the Python API as well as the server):
  - a conversation `context` longer than `max_len` keeps its newest turns (truncated from
    the start, not the end);
  - `noul` criteria keys are case-insensitive, and keys other than `true` / `false` raise
    `InvalidRequestError`, where they were silently replaced before;
  - `noul` accepts optional `labels`; `labels` on `choice` or `score` raise
    `InvalidRequestError`;
  - non-string `instructions` keep non-ASCII text instead of `\uXXXX` escapes;
  - `questions={}` returns empty answers with zero usage instead of raising;
  - a checkpoint temperature that is not a number loads with a warning and falls back to
    1.0.
- **New answer field:** `answer_confidence`, the probability of the chosen answer. Code that
  compares answer dicts key by key sees the new field and upstream's field order.
- **Parity tables.** The published v1.0 parity tables predate the new golden cases
  ([`docs/correctness.md`](https://github.com/tc3oliver/laya-apple/blob/main/docs/correctness.md#golden-set)).
  Routing thresholds and the published v1.0 and Switchyard measurements are unchanged.
